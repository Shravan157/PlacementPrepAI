# Agent Instructions

This file governs how an AI coding assistant (Claude Code, Cursor, etc.) should behave when working on this repository. Read this before generating or modifying any code.

## Non-negotiable constraints

1. **Do not deviate from ARCHITECTURE.md.** If a task seems to require a different library, pattern, or schema than what's documented there, stop and flag it — do not silently substitute.
2. **Do not scaffold ahead of the current phase.** Check PROGRESS.md before creating any file or folder. If a module is marked "Not started," do not create its folder, even empty, even as a placeholder.
3. **Do not introduce generic/off-topic content.** No sample data, seed scripts, or "for demonstration" content unrelated to the five core subjects (DSA, OS, DBMS, CN, OOP) or the stated features. This project has a history of scope creep via well-intentioned "helpful extras" — reject that pattern.
4. **Follow the locked module structure exactly**: each backend module gets `router.py`, `schemas.py`, `service.py`, `models.py`. Do not merge these into a single file for convenience, and do not invent a different pattern (e.g. class-based views, different file names) partway through.
5. **Normalized schema only.** `questions`, `answers`, `evaluations` are separate tables with foreign keys. Never suggest collapsing these into a single generic `messages` or `chat_log` table — this directly contradicts the project's stated differentiator.
6. **No pre-written Q&A pairs.** Questions are generated by the LLM from retrieved chunks at runtime. Do not create a static question bank or JSON file of canned questions, even temporarily "to get the UI working" — this is a repeated point of scope drift to avoid.
7. **Company tagging is by type only** (`mass_recruiter_it`, `product_based`, etc.), never by specific company name. Reject any request to add named-company data.

## Current phase gate

As of this file's last update, the active phase is **core modules only**: `auth/`, `core/`, `db/`, plus `main.py`, `config.py`, `dependencies.py`. See PROGRESS.md for the exact checklist.

Do not generate code for `practice/`, `evaluation/`, `resume/`, `rag/`, or `history/` unless PROGRESS.md has been updated to mark that module as active. If asked to build one of these prematurely, point back to PROGRESS.md and ask for confirmation the phase has actually changed.

## Style and conventions

- Backend: FastAPI + SQLAlchemy + Alembic. Pydantic v2 syntax for schemas.
- Auth: JWT via python-jose, password hashing via passlib[bcrypt].
- Config via `pydantic-settings`, reading from `.env` — never hardcode secrets, connection strings, or API keys in source files.
- Rate limiting via slowapi, applied at the router level.
- All DB access goes through SQLAlchemy sessions injected via FastAPI `Depends` — no raw connections opened inside route handlers.
- Tests go in `backend/tests/`, one file per module, named `test_<module>.py`.

## When in doubt

Prefer asking a clarifying question over guessing. This project prioritizes a small number of well-tested, defensible modules over broad but shallow coverage — building the wrong thing quickly is worse than pausing to confirm scope.
